Home Screen UI Spec

Problem Statement

Users currently see a home screen that mixes legacy UI patterns with partial dark‑mode support, resulting in visual inconsistency, cramped touch targets, and an unclear hierarchy of information. The experience feels dated compared to modern material‑design conventions and lacks a unified visual language that scales across the app.

Solution

Introduce a refreshed home screen that embraces a cohesive, glass‑based aesthetic, introduces clear typographic hierarchy, and provides a single, high‑seam testing point at HomeScreen.kt. The redesign will be driven by a lightweight token system to keep light and dark themes in sync and will expose a onTrackClick callback for future interaction hooks.

User Stories

  1. As a music listener, I want a greeting that reflects the time of day, so I feel personally addressed.
  2. As a listener, I want a quick‑play grid of my most recent tracks, so I can start playback with a single tap.
  3. As a fan of Last.fm, I want a translucent widget that shows my scrobble count and trend, so I can gauge my listening habits at a glance.
  4. As a power user, I want a persistent mini‑player at the bottom, so I can control playback without leaving the home screen.
  5. As a friend‑viewer, I want a clear visual cue when I’m looking at a friend’s profile, so I don’t mistake their data for my own.
  6. As a developer, I want the home screen to expose a single composable seam for testing, so UI tests are reliable and maintainable.
  7. As a designer, I want consistent spacing and token‑driven colors, so the UI automatically respects system light/dark modes.
  8. As an accessibility advocate, I want large touch targets and sufficient contrast, so the app is usable for all users.
  9. As a user with many tracks, I want pagination that loads more rows as I scroll, so the list remains performant.
  10. As a user interested in genres, I want a shortcut from the stats card to a genre‑explore screen, so I can discover new music.

Implementation Decisions

  • Modules: HomeScreen.kt, HomeHeader.kt, QuickPlayGrid.kt, LastFmMiniWidget.kt, and supporting view‑model HomeViewModel.
  • Interfaces: onTrackClick: (HomeTrack) -> Unit exposed from QuickPlayGrid; onSearchClick, onCastClick, onNotificationsClick, onProfileClick from HomeHeader.
  • Architecture: Keep all UI composables pure; UI state lives in HomeViewModel using Kotlin Flow.
  • Theme: Token‑driven palette defined in CSS; surface colors derived from MaterialTheme.colorScheme with slight opacity tweaks for glass effects.
  • Schema: No new backend schema; all data comes from existing HomeTrack repository objects.
  • API contracts: The home screen emits a TrackMenuTarget for context‑menu actions; no change to the public API.
  • Interaction: The quick‑play grid caps rows to six tracks (two rows of three) for visual balance; “View all” opens a full list screen.
  • Design tokens are defined in a separate Kotlin file HomeTheme.kt to keep the Compose layer in sync with the artifact CSS.

Testing Decisions

  • Focus on external behavior: verify that clicking a track invokes onTrackClick with the correct HomeTrack payload.
  • Validate visual hierarchy via screenshot tests (Compose UI testing with Paparazzi).
  • Cover the single seam HomeScreen – mock the view‑model and assert that the header, quick‑play grid, and stats widget render with correct data.
  • Prior art: existing unit tests for HomeViewModel and UI snapshot tests for other screens (e.g., DiscoverScreen).

Out of Scope

  • Full redesign of the discover and genre‑explore screens.
  • Backend changes to scrobble calculations – the widget reads the already‑computed stats.scrobbles value.
  • Custom animations beyond the built‑in Material ripple effects.

Further Notes

All colors are derived from the four core tokens (--color-bg, --color-surface, --color-primary, --color-accent) to guarantee a single‑seam theme switch. The design intentionally avoids a heavy hero image; the greeting text serves as the visual anchor, letting the glass widgets breathe.
